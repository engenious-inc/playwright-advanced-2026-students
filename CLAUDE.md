# AGENTS.md — instructions for AI coding agents working in this repo

Read this before generating, modifying, or running any code. These rules are non-negotiable.

## Project conventions

1. **Page Object Model is mandatory.** Every interaction with an anchor site goes through a class that extends `BasePage`. Never reference URLs or selectors directly in test files.
2. **Anchor adapters live in `shared/anchor-helpers/<anchor>/`.** Never put anchor-specific code outside this directory. If you need a new selector, add it to the adapter.
3. **Fixtures are typed.** All test fixtures live in `shared/fixtures/index.ts` and provide pre-instantiated page objects. Tests consume `test, expect` from `shared/fixtures/index.ts`, not from `@playwright/test`.
4. **Locators must be resilient.** Order of preference: `getByRole` → `getByLabel` → `getByText` → `getByTestId`. Never use raw CSS (`page.locator('.class')`) or XPath unless a comment explains why every preferred option failed.
5. **No `page.waitForTimeout`.** Use web-first assertions, locator auto-wait, or `page.waitForLoadState`. The lint rule will fail your build.
6. **No conditional logic in tests.** Tests assert; they don't branch. If you need branching, you're testing the wrong thing.
7. **All Playwright async calls must be awaited.** The lint rule `@typescript-eslint/no-floating-promises` will catch missed awaits.
8. **No `any`.** Use `unknown` and narrow if you genuinely don't know the type. The lint rule will fail your build.

## Anchor-specific rules

- **Tubi tests:** must respect `robots.txt`, use sensible delays between requests, and never make >1 request/second from a single IP. Tests that violate this trip Tubi's WAF.
- **Juice Shop tests:** assume `npm run juice-shop:up` has been run. Default URL is `http://localhost:3000`.
- **Expand Testing tests:** are best-effort — the site has occasional downtime; tests should retry once before failing.

## When generating new tests

1. Identify the **anchor slot** the test belongs to (primary / controlled-secondary / edge-case)
2. Use the existing fixture (`tubiHome`, `juiceShopHome`, etc.) — don't instantiate page objects inline
3. Write the test name as a behavior assertion ("plays the first hero video" — not "clicks the play button")
4. Add `await expect(...).toBeVisible()` checks before interactions to surface flakiness early
5. **Never include `if`/`else`/`try`/`catch` in a test.** If the path branches, write two tests.

## Forbidden patterns

**Enforced by lint + CI** — your build fails (the rule that catches it is named):

- `page.waitForTimeout(...)` — use proper waits (`playwright/no-wait-for-timeout`)
- Raw `setTimeout` inside test bodies (`no-restricted-syntax`)
- `// @ts-ignore` / `// @ts-expect-error` without a description (`@typescript-eslint/ban-ts-comment`)
- Hardcoded `http(s)://` URLs in test files — they belong in adapter `endpoints.ts` (`no-restricted-syntax`)
- `console.log` in test files — use `test.info().annotations` (`no-console`)
- `any` (`@typescript-eslint/no-explicit-any`)
- Unawaited Playwright calls (`@typescript-eslint/no-floating-promises`)

**Enforced by review** — convention, not mechanically lintable (this gap is itself the M09 lesson: lint is a safety net, not a substitute for judgment):

- `await page.locator(css).click()` where `getByRole` would work. Raw CSS/XPath is allowed in **adapters only**, and only with a comment explaining why every preferred locator (rule 4) failed.

## When fixing failing tests

Before changing the test:

1. Check the trace (`npm run trace test-results/<test>.zip`) to see what the page actually did
2. If a selector broke, fix it in the **adapter**, not the test
3. If behavior changed, update the **adapter method**, not the test assertion
4. Only modify a test file when the test's _intent_ should change

## When asked to add a new feature to the repo

1. Update the adapter(s) first
2. Update fixtures if a new page object was added
3. Add tests last
4. Run `npm run verify` before declaring done
